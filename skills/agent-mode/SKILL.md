# Agent Mode

你可以使用 Agent Lab 把当前 AstrBot 会话切换到受控 Agent Mode。Agent Mode 不是替换当前 bot，也不是完全隔离记忆，而是让当前 bot 在任务期间使用独立任务状态、入口/出口摘要、工具 profile、审批协议和心跳续跑。

## v0.2.4 项目、反问和管理员优先（优先于旧章节）

- Agent Lab 是 Bot 自己的项目工具。主模型、角色和平台仍由 AstrBot 提供；日常聊天不要另起与后台项目重复的执行循环。
- 先用 `agent_lab_project(action="list")` 查看项目。相关任务复用已有项目；新类别用 create 建项目并分类，select 选择新任务的归属。创建任务可传 project_id/project_title/category，或让规划阶段建议归类。
- 用标题和简洁简介选择画布方案。项目常用方案会优先列出，没有合适方案就略过。不要为了一个简单任务强行套流程。
- `handoff_summary` 只传与当前任务有关的目标、限制和资料引用，不复制日常聊天全文。项目只读取本项目交接摘要；旧日志按需查询。
- 每完成一个里程碑，用 `agent_lab_project(action="summary", summary="...")` 保存项目摘要：已确认成果、未验证项、文件引用、下一步。摘要不是权限，也不是测试证明。
- 日常读取进度/记忆只返回精简状态和摘要。不要把项目完整工具历史粘贴回日常。默认不自动共享摘要；管理员开启项目互通后才自动注入最多800字。
- 有明确缺失且影响结果的信息时，用 `agent_lab_ask_question(question, options_json, recommendation)` 提出一个具体问题、2–4个选项及推荐理由。先读资料，不问本可自行查明的问题；不能代替管理员选答案。
- 管理员使用 `/al finish`、`/al cancel`、“停止当前任务”或“按现状交付”，优先于计划完整性、审批和验证缺口。系统直接结束并记录未完成项；不要反复阻止或要求重复审批。
- `switch` 切换任务保留原任务检查点并暂停；切换不等于恢复执行。已结束任务只读，在同项目新建后续任务。
- 前端心跳/定时已移除，连续任务由执行事件推进。不要建议开启心跳。
- 开发前优先使用当前 Bot 已安装且获准的 Git/GitHub 或快照工具留痕。上下文rollback只恢复聊天；配置快照不代表数据库或外部API可撤销。恢复前说明范围并由管理员确认，不能自动硬重置源码。
- 项目页展示记录文件、缓存、任务对话内容大小，清理先预览再确认。模型不能静默删除项目历史；源码目录不属于项目缓存清理范围。


## v0.2.3 任务连续性（优先于旧心跳说明）

- 你仍使用 AstrBot 当前会话的模型、身份和工具；Agent Lab 是你的项目管理工具。
- 可用 `agent_lab_workflow_catalog` 按标题和简介寻找合适画布。没有合适方案时，`agent_lab_enter_mode(workflow_mode="none")` 跳过画布；选定时传 `workflow_mode="selected", agent_id=...`。
- 每个任务有具体计划。可在进入时传 plan_json，或随后用 `agent_lab_submit_plan(steps_json, constraints)` 提交；计划由管理员通过现有审批入口批准。
- 批准后系统自动续轮，不需要反复 tick 或开心跳。定时模块只负责到期/周期触发。
- 工具结果附带证据 ID；使用 `agent_lab_checkpoint(step_id, summary, evidence_json, completed)` 写回当前具体步骤。分析汇总可使用 `agent_lab_record_report` 保存实际报告；不能以报告代替测试证明。
- 管理员途中补充要求用 `agent_lab_steer` 转交，不重建任务，不把日常闲聊自动记成约束。
- 原始目标、批准计划、步骤、约束和详细任务对话独立保存。压缩后按持久状态续接；结果未知的外部操作先核对，不盲目重放。
- 日常聊天只交换摘要或明确资料。无画布时不要调用推进画布游标；有画布时保留节点、循环、并行与子代理语义。
- 计划/工具审批不能由模型自行批准。暂停、拒绝、取消、预算上限均停止自动续轮。


## 何时进入

在这些场景中考虑进入 Agent Mode：

- 用户要求你“自己推进”“后台继续”“任务模式”“配置项目”“写插件”“部署”“排错”。
- 任务需要多轮工具调用、测试、等待、复盘、归档。
- 普通聊天上下文和记忆插件可能干扰工程判断。

如果当前 Agent 配置是 `manual`，不要自动进入。  
如果是 `confirm`，先说明原因并请用户确认。  
如果是 `smart`，低风险资料整理可自动进入；涉及文件写入、命令执行、部署、删除、密钥读取必须确认。  
如果是 `always`，尽量使用 Agent Mode，但危险动作仍需审批。

## 自主判断流程

每次用户提出可执行任务时，先按当前 AgentSpec 做一次轻量判断，而不是机械进入或机械拒绝：

1. 判断任务是否真的需要 Agent Mode。普通问答、短聊天、一次性解释不进入；多步骤工程、排错、部署、资料整理、需要状态保存或心跳的任务才进入。
2. 如果已经存在 active task，不要重复进入；先调用 `agent_lab_read_state` 读取当前任务，再继续、暂停、审批或退出。
3. 按 `trigger_mode` 决策：
   - `manual`：只有用户明确说“进入任务模式/Agent Mode”、使用命令或 WebUI 时才进入。
   - `confirm`：判断适合进入时，用一句话说明原因并等待用户同意；同意后调用 `agent_lab_enter_mode(user_confirmed=true)`。
   - `smart`：低风险、非破坏性的整理/计划/分析可自主进入；一旦涉及文件写入、命令执行、部署、删除、读取密钥或关闭插件，先确认。
   - `always`：除非只是闲聊或简单问答，否则优先进入 Agent Mode；危险动作仍必须审批。
4. 进入时保留当前 bot 原本的身份、语气与关系，但把刚才商量出的计划压缩成 task_brief；不要把闲聊碎片当成任务依据。
5. 根据 AgentSpec 的工具、插件、skills 和外部集成蓝图选择工作方式。被关闭的插件不要依赖；对应插件关闭时，其注册工具也视为不可用；未选择的高风险工具不要主动调用。
6. 心跳不是连续性的来源，只是唤醒机制。只有任务确实需要等待、长时间跑测试、部署观察或用户明确要求时，才建议或开启心跳。
7. 入口和出口是工作流节点的一部分：entry/entry_gate/context_bridge 定义如何开启，archive/exit_summary 定义如何结束。不要绕过这些节点直接把普通聊天当成任务状态。

## 可用工具

- `agent_lab_enter_mode`：创建任务状态并进入 Agent Mode。
- `agent_lab_read_state`：读取当前任务状态。心跳醒来或长任务继续前必须先用。
- `agent_lab_update_state`：写回当前进度、观察、下一步和阻塞点。每轮结束前必须用。
- `agent_lab_advance_workflow`：记录当前工作流节点结果并推进到下一节点；多分支、并行分支、审批/校验节点必须用它留下轨迹。
- `agent_lab_read_task_memory`：读取已归档并暴露的任务记忆；普通模式也可以按标签或关键词查询续写上下文。
- `agent_lab_update_workflow`：检查、增删改工作流节点和连线；适合用户要求改入口、审批、API、插件模块、工具模块、并行分支、节点提示词、记忆或出口规则时使用。
- `agent_lab_run_parallel_workflow`：运行画布中 `parallel_branch` 后续工作包；API 节点调用已注册 API，提示词/插件/工具节点以受限工作包执行，结果写入 task_state。
- `agent_lab_tick`：推进当前任务一轮。
- `agent_lab_request_approval`：危险操作前请求审批。
- `agent_lab_set_heartbeat`：为长任务开启/关闭心跳。
- `agent_lab_finish`：完成任务、出口摘要、归档退出。

## 任务连续性

任务连续性来自 `task_state`，不是来自旧聊天上下文。每一轮必须：

1. 读取并复盘当前任务状态。
2. 明确本轮只推进一个有限工作单元。
3. 工具调用后总结观察结果。
4. 调用 `agent_lab_update_state` 写回进度、关键改动点、验证结果、下一步、阻塞点。
5. 调用 `agent_lab_advance_workflow` 记录本轮完成或选择的节点；多分支必须明确 next_node_id 和选择原因。
6. 判断是否完成、暂停、请求审批或需要心跳。
7. 任务过程中的时间线和成果属于任务记忆，不直接污染普通聊天记忆；退出时再生成可回流的候选。
8. 修改工作流后先用 `agent_lab_update_workflow operation=check` 检查入口、出口、入口摘要、隔离快照、任务记忆、审批/人工闸门、不可达节点和模块引用；工作流改变任务模式规则，不改变 bot 身份。
9. 插件、API、工具、skill 都只是任务模式模块：绑定时写清 `ref_type/ref_id`，必要时补 `prompt`、`condition` 或 `parallel_group`，不要绕过 AgentSpec 的隔离和白名单。
10. 遇到 `parallel_branch` 节点时，优先用 `agent_lab_run_parallel_workflow` 执行后续可并行工作包。子工作包只能产出证据、结论、风险和合并字段，不能直接完成或退出任务。

## 审批规则

这些动作前必须先调用 `agent_lab_request_approval` 或自然语言询问用户：

- 删除文件、批量覆盖、清空目录。
- `git reset`、`git clean`、回滚大量代码。
- 部署、重启服务、修改系统/全局配置。
- 读取或暴露密钥、令牌、账号。
- 数据库破坏性迁移或删除。

这些动作通常无需审批：

- 读取文件、列目录、查看日志。
- 创建/更新 Agent Lab 自己的任务状态。
- 小范围明确文件编辑。
- 运行测试、查看 `git diff/status`。

## 心跳

心跳只用于真正长任务。开启前确认用户允许，或在 smart/always 模式下判断任务确实需要持续推进。

心跳醒来后必须：

1. 先读 task_state。
2. 再执行有限步骤。
3. 立刻保存进度。
4. 同类失败三次后暂停并请求人工介入。

## 退出

完成任务时调用 `agent_lab_finish`。出口摘要必须包含：

- 完成情况。
- 关键修改/结果。
- 验证方式和验证结果。
- 遗留问题。
- 下次续写入口。
- 可回流长期记忆候选和标签。
