# v0.4.1 核实与更新

日期：2026-11-25。承接小莫两轮体验反馈，保留v0.4的五工具、历史前缀稳定性和自主执行方式。

## 核实结论

1. **默认工作目录误判已复现。** Python中`subprocess.run([...])`的继承cwd被递归检查代码作为显式`cwd`参数传入。即使Node只检查授权文件，也会因为进程启动目录在会话workspace而被判越界。Shell直接执行同一检查没有这项伪目标，形成口径差异。
2. **“scope_notice导致批准后拦截”不是现有代码的直接因果。** v0.4原代码在匹配到已批准签名后已跳过`review`拒绝分支；`scope_notice`仅记录提示。`batch_failed`在工具返回错误或无有效结果后产生。本地没有`approval_1f7b089ec58c`/`task_9aad5b3c0d44`原始任务及usage账本，不能据这条提示断言当次调用具体为何失败。
3. **0步骤状态确有代码来源。** 普通任务清单与旧画布状态视图没有完全接通；画布为空时旧视图会生成0步骤计划。清单本身仍在task_control中，属于显示/日志投影问题。
4. **全量写入参数确会增加后续输入。** 已生成的大段工具参数需要保留调用协议和签名；不能为了省字符在每轮请求前回写旧历史。Python代码文件体积本身也不会自动转化为发给模型的Token，必须区分模块导入与提示/Schema注入。此次没有重新实现“动态折叠写入参数”的中间层，也没有新增大写入强制交接阈值；降低这部分开销主要依靠局部编辑引导和按原容量边界进行的交接，不保证模型一定选择最省Token的方法。
5. **空白画布与未应用画布之前没有统一。** `selected`加零节点仍可能选择画布提示、旧控制工具及画布轮次预算；现在以实际任务快照中的节点共同判定。旧“空白”前端模板还偷偷创建一个监听入口，改为真正零节点。

## 改动与效果

- 继承cwd只负责解析相对路径，不是额外访问目标；显式cwd、实际范围外文件、敏感文件与破坏性命令继续检查。没有把整个workspace默认加入授权目录。
- 已批准的精确工具名、参数、当前授权/步骤/输入/宿主配置签名先匹配，使用一次性授权，完全跳过普通范围评估与workspace解析；不会永久扩大roots。管理员暂停、已拒绝动作、只读、工具禁用与硬预算仍优先。
- 失败记录增加阶段、原始错误和真实结果路径；执行上下文建立失败、工具空返回和执行中异常均保留记录。执行中异常为未知结果，禁止自动盲目重放；不会把上一项成功结果路径当作下一项失败结果。
- 普通任务的旧状态视图直接映射真实清单及当前步骤，不再另建0步骤计划。
- 空白方案带`canvas_kind=blank`标签，旧零节点selected任务自动按无画布模式运行，保留请求模式供核对，不改权限、步骤或授权版本。没有节点时不注入画布提示、旧控制工具和每轮工具/Token/240秒限制；管理员总预算保持有效。有实际节点的画布必须显式选用才执行。
- 方案设置用独立保存入口，只合并工具、插件和行为指引字段到最新保存方案；不提交画布草稿、不覆盖节点连线或自动填节点。无画布任务也使用方案自定义指引。画布Python模块仍可为WebUI与有节点方案导入；这不意味着它的源码会发给模型，空白任务跳过的是画布提示、Schema及执行分支。
- 新建方案的前端工具总预算缺省值统一为0不限；已有120/240等明确预算保留。默认240秒仅用于实际画布轮次，普通任务没有此轮次截止。
- 已有文件优先搜索和局部`file_edit`，新建或整体重构仍可全量写入。这是行为引导，没有加入新的行数/写入上限或自动篡改工具参数。
- `usage.jsonl`与任务线增加system字符、工具定义字符、工具调用参数字符、其中全量写入正文字符；缓存Token单列并标明以模型报告为准。可以直接观察大文件全量写入造成的后续输入增长，不宣称一定节省一半。
