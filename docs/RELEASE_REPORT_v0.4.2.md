# v0.4.2：增量唤醒、会话工作区与交接回执

## 核实范围

本地没有`task_b91bd01b2a01`原始任务档案及其`usage.jsonl`。843226 Token、24次请求、26分钟和8条审批为用户转述，不能冒充独立核实的线上数据。代码确认了三处机制：每次普通任务唤醒生成完整计划提示；会话workspace未作为默认执行范围；交接最近窗口可能保留成功写入的完整参数。

## 改动

1. **同周期首次完整输入，后续只追加变化。** 新`wake_context.py`给首次任务输入提供目标、原始简报、验收、约束、计划与权限；下一次唤醒通过历史中确实存在的标记找到不可变快照，只发变更字段。勾选步骤只发状态变化，不重发步骤指令。新管理员要求和审批执行回执只补入一次，不附原脚本。模型请求失败后，已保存在历史中的任务输入继续使用，不重复复制。交接开始新周期后会重新提供一次完整要求，防止只剩增量而丢失原需求。原有历史不回写，worker的独立指令不替换。
2. **当前会话workspace成为默认工作范围。** 只使用宿主`workspace_root_for_context`返回的真实绝对目录；不相信模型参数里的cwd，不猜`workspaces/<UMO>`，不放开workspaces父目录或其他会话。项目授权roots不被永久改写。敏感凭据、递归清空、破坏数据库/系统及只读档限制保留；真实symlink/junction和路径穿越仍检查。宿主版本无法解析工作区时不凭猜测扩大权限。批准调用绑定实际工作区，审批等待期间切换工作区会使旧批次过期。
3. **大参数在交接边界变为独立操作事实。** 同周期内不改写已发送的调用、签名或工具结果。正常阶段/容量交接先原样归档，然后只对成功且与真实账本精确匹配的大写入/执行调用，将整组assistant调用与全部tool结果移出新周期，生成普通事实回执。摘要材料及保留窗口均使用回执，记录路径、原参数/正文字符数、状态、关键输出和绝对归档路径。普通读取、失败、未知、未执行或找不到成功记录的调用保留；并行组任一项不能确认就保留整组。审批工具还须匹配完整批次、管理员决定和每项真实执行结果，不能把“批准”当“执行成功”。

回执整理候选采用8192字符起点，只影响交接时是否值得替换，不限制调用、读写范围或模型输出；没有新建大写入强制交接。旧回执使用正常最近窗口预算，不永久全量钉住；150条旧回执的容量压力测试不会靠无止境保留把任务暂停。完整内容仍在归档，可直接按文件路径读取。

另修正自动交付的暂停入口：暂停期间不为关联证据而重新保存任务，避免无意义更新时间覆盖管理员保护状态。进度、审批和结果正文继续由来源Bot撰写。任务与日常Conversation隔离不变。
