# v0.2.4 交付报告

日期：2026-11-11。基于 v0.2.3 增量修改，继续适配 AstrBot 4.29.4。

## 这次的产品变化

插件默认进入项目目录，Bot 可以创建、选择项目，将同类任务归入同一项目。项目下每次任务独立保留目标、计划、证据、问答和交付说明；日常聊天只控制任务、接收必要通知和筛选摘要。

保留原全屏画布、模块素材、条件/循环、并行、子代理泳道、工具/API配置和配色。画布仍是可选流程指导：项目可标记常用方案，Bot 按标题和简介选择，无合适方案就跳过。前端不要求另选主模型。

## 前端完成项

- 项目目录树：展开/收起项目，查看任务状态、待回答标记，任务分类与移动。
- 项目详情：任务、摘要与存储、常用方案、开发保护四个明确区域；完整任务记录按需查看。
- 任务详情：计划、工具审批、结构化反问、途中引导、切换/继续/暂停、管理员停止和按现状交付。
- 画布初始缩放72%，比例可选；窄iframe默认减少遮挡。坐标变换仍由原画布负责，不使用会破坏拖拽坐标的整页CSS zoom。
- 素材库左右换边、拖动/键盘调宽、平滑收起；标题和操作栏常驻可见，参数抽屉可明确关闭。
- 项目树与素材库开合保留DOM并使用状态过渡，避免每次重建使过渡失效；抽屉退出、卡片反馈、选项悬停与焦点可见。
- 任务表单与摘要草稿按项目/任务保留，静默刷新不替换未提交文字；无变化时不重新绘制项目页。
- 请求有忙碌状态、重复点击保护与超时提示；未知工具结果有核对入口，报错有可见反馈。
- 心跳/定时启动入口从前端撤下；原保存图不会被自动清空。

## 管理员不再被交付规则卡住

`/al finish`、`/al cancel`、项目页交付/停止，以及明确文本“停止当前任务”“按现状交付”，进入独立管理员结束路径。

这条路径在模型验收之前执行，先持久化终态标记，随后取消属于该任务的后台循环并归档。它不调用模型来决定是否允许结束，也不要求全部步骤完成或先通过所有工具审批。未完成项、未验证项与操作者记录在交付说明中。

原生工具可能已经对外部系统产生副作用，停止不等于撤销这些副作用。未知结果仍留档；管理员可以按现状结束，不被迫先解决未知结果才能退出。晚到结果不能重新生成活动任务，晚到自动交付不能覆盖管理员结果。

## 反问与途中引导

Bot 在关键目标/范围缺失时可以提出一个明确问题，给出2–4项选择和推荐理由，管理员也可以自由回答。问题、答案、时间、回答者持久保存。

答案先进入任务约束再恢复；未形成计划时重新草拟计划，有批准计划时继续执行。管理员主动恢复可以跳过待答问题，Bot 被告知只能先做不依赖该答案的部分。暂停、停止、交付仍是独立控制操作，不由反问系统否决。

内置技能要求先查项目资料，避免询问能自行确认的信息，也不把推荐选项当成用户已选择。

## 日常与任务隔离的实现

1. 立项接收显式筛选的 `handoff_summary`，不再扫描整个日常对话历史作为入口。
2. 执行仍使用稳定 task_id 派生的原生 conversation_id；不切换日常 `sel_conv_id`，不在日常对话里追加工具轮次。
3. 私有执行事件使用副本和独立标记，避免污染来源事件。任务工具过程只写任务日志，不逐次发回日常聊天。
4. 日常请求仅加入简短工具说明和当前任务ID/状态；不再自动放入整份工作流和全局历史模式。
5. 日常自动互通需项目明确开启，最多800字；显式查询项目摘要最多1600字；任务自动读取同项目交接最多3500字。权限/计划保留精确数据，不靠摘要重建。
6. 任务切换暂停原任务并保留检查点；只有显式选择操作能替换活动任务指针，旧任务保存不会抢回当前会话。

这些限制控制自动注入的体积，不承诺模型上下文无限或资源完全独占。CPU、API限额和共享源码目录仍可能共同使用；本版同一来源只推进一个活动任务。

## 存储透明与清理范围

项目索引与摘要保存为插件数据目录下的普通 JSON/Markdown；原任务记录继续使用既有文件。界面展示：

- 项目和任务实际记录文件大小、可清理JSONL日志大小。
- 任务文件相对路径和只读内容预览。
- 原生任务对话的 UTF-8 内容大小，单独列示，不冒充SQLite数据库可立即释放的磁盘空间。
- 共用索引/历史记忆文件大小，避免重复分摊到每个项目。

清理分为缓存、任务历史、整个项目。先生成范围清单、文件大小、任务内容摘要和校验token，再确认。期间数据改变必须重新预览；运行任务需先暂停并收尾。

缓存清理保留计划、约束、摘要、证据编号和必要恢复数据。删除历史/项目会清理相应文件、关联记忆及精确任务conversation，并移除已删除任务的历史模板来源。不会递归删除管理员的源码工作目录。

少量终态标记保留用于拒绝晚到回调，纳入共用元数据统计。清理中断会留下状态记录，需重新预览剩余内容；跨文件与原生数据库清理并非一个统一事务，不宣称瞬间全有或全无。

## 后端职责

- `Projects`：目录索引、任务归属、摘要、切换、管理员结束与受管存储范围。
- `WorkspaceAPI`：已认证项目操作接口；前端按钮调用明确动作，不复用错误的活动任务指针。
- `TaskControl`：计划与执行仍沿用原内核，新增问题/回答状态与项目自动分类建议。
- `AgentLabStorage`：终态标记和活动指针保护，防止任务复活。
- `AstrBotBridge`：独立任务事件与conversation，载入同项目过滤摘要；终态后不再写入对话。
- `ProjectUI` 与 `workspace.css`：项目界面和iframe布局增量层，原画布业务保留。

这次没有引入另一套Agent框架或第二个模型配置，也没有新造任意代码回滚执行器。

- [OpenAI 官方持续任务文档](https://learn.chatgpt.com/docs/long-running-work)：明确目标/约束/验收、运行中引导、相关任务归项目。
- [Claude Code 交互文档](https://code.claude.com/docs/en/interactive-mode)：区分途中输入、排队与中断；反问使用明确问题和可选答案。
- [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)：继续使用前版事件续轮与未知结果处理的思路。
- [GitLink](https://github.com/SGSxingchen/astrbot_plugin_gitlink)：复用Bot已注册的Git/GitHub工具。
- [Snapshot Guard](https://github.com/xuanbaon/astrbot_plugin_snapshot_guard)：参考配置/状态快照和回档前备份的边界；界面发现已安装工具并给出项目链接。
- [Rollback](https://github.com/TheEyeoftheUniverse/astrbot_plugin_rollback)：它回退聊天上下文，不等于代码回滚，未将其包装成万能恢复按钮。
- 使用 UI/UX Pro Max 的布局、反馈、低成本动效和减少动态效果规则；沿用现有绿色系统，不直接套用技能推荐的新配色。

本轮延续维护者先前要求：不启动AstrBot、不调用真实模型/工具、不做浏览器实际手感测试。完成Python AST、JavaScript语法、资源/API对应和十项源码契约检查；详见 [验证与评分报告](VALIDATION_v0.2.4.md)。

“大赛级”视觉与丝滑程度不能通过源码评分保证；本版交付的是已连接后端、可供真实体验的实现，不把未做的浏览器验证写成通过。实测后仍可按原布局继续微调比例、留白、拖拽反馈和动效节奏。
