# Agent Lab v0.3.0 更新报告

日期：2026-11-10。对照 AstrBot 正式版：4.29.4。此次是任务内核和前端重构，运行方式与 v0.2 不同。

## 本版解决什么

以前长任务主要依赖当前模型上下文和主动写回状态。多轮工具调用、截断或模型停轮之后，管理员可能需要重新查日志、提示计划。现在任务具有独立编号、明确的批准计划版本、步骤状态、工具调用记录和接续位置；模型停一轮后，执行器根据持久状态决定继续、等待或停止。

本版不是“无限上下文”或“任何中断都能无条件恢复”。它把目标、约束、授权、步骤和记录从可被压缩的聊天历史中分离，并为未知外部操作结果提供人工核对。

## 后端与任务逻辑

| 变化 | 实际行为 |
| --- | --- |
| 批准计划 | 立项后先生成计划；管理员确认版本后开始。保存批准人和时间；修订生成新版本，完成的步骤不重写。 |
| 持久执行 | SQLite 存任务、步骤、审批、调用、事件、模板和记忆；工具派发前先提交意图，结果返回后提交结果。 |
| 自动续接 | 每步有限模型轮次，剩余工作自动再排队；审批、阻塞、暂停时不再持续调用模型。总预算不会因换轮清零。 |
| 防循环 | 限制轮数、调用数、Token、超时、重复错误与无进展次数。进展按实际结果指纹判断，新调用 ID 或换一种说法不算进展。 |
| 途中引导 | 引导当前任务、后续请求、资料注入分开。管理员约束完整进入持久任务字段；规划期间收到新约束会重新规划。 |
| 暂停与取消 | 阻止下一次工具派发，取消运行协程；可管理的原生命令进程尝试终止。已发生的外部副作用不能假装回滚。 |
| 未知结果 | 超时/中断后的操作标为 unknown，管理员核对实际结果并填写依据后，才可明确恢复。 |
| 完成验收 | 步骤完成必须有本任务、本步骤、当前版本的成功调用证据或真实保存的报告。全部步骤完成后等待管理员验收。保存报告不等于证明测试或部署成功。 |
| 定时模块 | 一次性批准并定时开始。只检查到期时间，不定期调用模型思考。周期任务、循环图和并行子代理本版未开放。 |

代码职责分工：`main.py` 只负责身份、命令、API；`harness_store.py` 负责事务数据；`harness_engine.py` 负责生命周期与调度；`harness_adapter.py` 负责 AstrBot 会话、模型、工作目录；`harness_tools.py` 负责执行前检查和工具结果。

## 原生适配和权限

- 对齐 AstrBot 4.29.4 的 `AstrAgentContext`、原生工具执行器、模型 runner 和摘要压缩参数。
- 每个任务绑定插件内部原生 ChatUI session/conversation；日常会话当前对话不改变。工作台是任务入口，不要求普通 ChatUI 侧栏展示内部会话。
- 直接修改模式通过原生项目工作目录绑定管理员指定路径；沙盒模式严格使用已配置沙盒，不回退本地执行。
- 管理员 ID 来自 AstrBot 配置与插件明确授权配置；模型没有审批工具，不能自行批准计划或危险操作。
- 默认完全禁用群聊。第三方工具只能在 direct 模式、服务器白名单和任务选择范围内使用，并保留框架权限包装。
- 审批绑定任务、步骤、计划版本、工具、参数和资源摘要；API 地址、凭证或执行配置改变时，旧审批不能继续使用。
- 独立控制台默认关闭，任何监听地址都必须配置 Token；原生插件页使用 Dashboard 已认证身份。
- 内置报告工具只保存私有候选产物，不会自行共享记忆。

原生工具本身的本地权限、网络策略、沙盒能力仍然有效。Docker 容器路径不等于独立于数据卷的沙盒，选择直接修改时应按实际容器挂载理解工作目录。

## 前端与按钮对应关系

前端采用 React + TypeScript + React Flow，静态产物包含在仓库中，使用者无需编译。

| 页面操作 | 后端行为 |
| --- | --- |
| 创建任务 | 校验目标、工具范围、执行环境与模型；保存任务，生成待审批计划 |
| 批准计划 / 定时开始 | 对明确版本批准，立即排队或保存一次性安排 |
| 暂停 / 恢复 / 取消 | 改变持久状态并控制队列及进行中协程 |
| 修订计划 | 保存新版本，过期旧审批，保留已完成步骤 |
| 批准 / 拒绝工具 | 精确审批记录；批准后在任务仍处于等待审批时续接，用户主动暂停不会被覆盖 |
| 核对未知结果 | 保存人工核对依据；不隐式恢复任务 |
| 验收 | 只允许全部步骤完成、等待验收的任务进入完成状态 |
| 删除任务 | 按明确 task_id 停止并软删除任务及其可见记忆，不按会话误操作其他任务；内部调用审计保留，不清空外部工作目录 |
| 途中引导 | 写入任务收件箱或后续请求记录，不并发启动第二个任务执行器 |
| 保存任务资料 / 项目共享 | 默认仅当前任务；明确确认后按 project_key 共享 |
| 保存模板 | 校验实际节点与无环连接，模板与任务实例分开 |
| API/凭证管理 | 实际保存/更新/删除注册信息，凭证加密保存，返回脱敏内容 |

画布支持拖动、端口连线、重接、拖线到空白添加并连接节点、框选、多选拖动、删除、撤销重做、视口缩放、结构检查。只读运行图禁止修改，参数面板独立于画布。默认连线不持续播放装饰动画。

状态使用 SSE 按事件更新对应任务；断线才回退轮询。草稿与后台状态分开，拖动期间不反复写浏览器存储。失败显示错误，不以固定成功提示掩盖拒绝结果。

## 升级处理与功能收敛

1. v0.2 文件保留，旧活动任务和归档以只读形式展示。不会自动把旧计划拿来执行。
2. 停止旧版插件注册的心跳/工作流定时回调，恢复保存过的日常插件隔离快照。
3. 已安装的旧 Agent Lab `agent-mode` 技能先备份再更新，避免残留调用已经停用的工具。
4. 原注册 API 和凭证继续可读写；旧记忆不会自动注入普通聊天或新任务。
5. 旧复杂画布不做有损自动迁移。新画布提供三个真实节点：Agent 步骤、工具调用、审批门。复杂循环、并行子代理、外部框架蓝图和登录态伪刷新不作为本版可执行入口。
6. `scripts/*smoke*`、旧 preview、旧 runtime 模块属于历史资料，不由新入口注册，也不作为本版检查通过的依据。

## 已完成的检查

- Python AST 静态解析；不导入插件、不运行任务代码。
- JSON 配置与前后端版本一致性、API handler 存在性、生产资源引用检查。
- TypeScript `tsc --noEmit` 和 Vite 生产构建。
- `git diff --check`。
- 对照官方 4.29.4 源码，人工核对会话/数据库签名、工具上下文与执行器、权限包装、SSE 的原生/独立传输以及命令进程轮询协议。
- 静态交叉审查批准/暂停/取消/删除/未知结果/记忆共享/修订计划/工具命名/前端按钮调用链。

**按维护者要求未运行：AstrBot 实例、模型请求、真实工具、数据库任务行为测试、端到端测试、浏览器交互或手感测试。** “静态检查通过”不等于“所有部署环境实测通过”。

## 部署后建议验收

优先验收：管理员与群禁用边界；创建后不执行、批准后执行；多轮后定位同一步；审批前工具没有副作用；途中新增限制不丢失；暂停/取消不被自动续跑覆盖；重启后未知结果需核对；删除旧任务不影响其他任务；资料不会无确认跨项目共享；画布刷新不丢草稿。

再按实际 Docker/Linux/Windows 配置检查文件、命令、Python、注册 API、沙盒连通、超时和通知。画布拖拽手感与按钮布局由维护者实际体验后继续调整。

已知边界：同一任务图的独立分支本版仍顺序执行；总 Token 预算在调用间检查，单次请求可能超出剩余额度；SQLite 同步事务在很慢的磁盘上可能造成短暂等待；不保证撤销已发送的 API 或已产生的外部写入；使用超大任务资料仍受模型上下文上限约束。
