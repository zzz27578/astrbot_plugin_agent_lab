- `_review_revision`：取消第二个模型审查普通计划微调。
- 步骤完成后的 `stop_runner()`、24k/1200/4k隐藏限制、降级强制重读指令及每24次工具切轮。
- 分字符减重及120行缓存的旧测试，替换为实际上下文驱动的可用性测试。

## 普通后台的五个控制工具

所有参数为字符串，JSON复杂对象使用JSON文本；Schema总量约3.2KB，最终实测见验证报告。

| 名称 | 参数 |
|---|---|
| `task_plan` | `steps_json`，可选`constraints/summary/completed_step/message` |
| `task_progress` | `message` |
| `task_ask` | `question/options_json`，可选`recommendation` |
| `task_approve` | `operation/reason/impact/operations_json`，可选`rollback/message` |
| `task_finish` | `final_summary`，可选`memory_candidates/message` |

宿主文件、Shell/Python和用户选择的插件执行工具仍按权限提供。这五个是控制工具的精确集合，不是全部可执行工具数量。初始计划和扩大目标/授权需管理员批准，普通拆分、重排和勾选不重新审批、不打断当前循环。交付自动关联同授权下真实执行记录，核对改动文件及最后写入后的成功验证；这不能替代功能正确性的人工体验。

## 历史与压缩

1. 工具返回立即将完整原文落到任务数据目录。最多展示32KiB UTF-8，若超长则附总字符数、实际绝对路径。只处理这一次；写入历史后不再重算展示或改写旧参数、签名。
2. `capacity = min(管理员配置容量, 已知provider/宿主容量)`；未知容量默认128000。达到`capacity * context_percent / 100`，或显式阶段切换，才压缩。轮数与工具总次数不触发压缩。
3. 先原样归档，再发一次摘要请求；摘要材料移除推理/签名元数据，保留实际业务正文及参数。字数使用管理员`summary_chars`，不按步骤数改写。超长按段落/句子边界收尾，无二次摘要调用。
4. 压缩后目标保留触发容量25%的最近完整工具调用组。最新正在使用的工具组优先；仍能放进真实容量时允许超过25%目标。空返回、单次超时或provider错误用最近工作窗口继续，不要求重读。若连最新完整组也无法容纳且无可用摘要，保存原历史并给出明确容量错误，不空手续跑。
5. 日常与任务Conversation独立；阶段压缩只作用任务Conversation。管理员要求变更是新的输入，已入历史的内容不被回写。

## 底线与验证

目录内普通开发放行；明确越界、递归清空、凭据与破坏性命令先主动请示，后端拒绝不代发卡。命令静态检查仅为底线防护，不能证明任意脚本无副作用；宿主/操作系统的隔离继续生效。

同工具等价错误第3次提醒、第5次暂停；最近20次记录中18次高度重叠读取先提醒，继续6次才暂停。新路径、非重叠区域与实际新改动不按空转处理。上述是可复核的异常判据，不是总工作量上限。

总Token、总耗时和管理员显式总调用预算仍是硬线。单个已发出的API请求无法预知最终用量，返回后立即检查；未上报Token单独记录输入估算，不伪装为真实账单。总耗时从任务创建开始，包含等待和暂停。

测试必须经过真实bridge请求边界，逐字节比较同周期历史前缀；≥1800行源码的决策依赖实际上下文，真实精确修改及独立子进程验证后才完成。另验新建、续写、删除、研究、交接异常、管理员控制、隔离和安全边界。离线状态驱动provider只能验证这些机制，不能替代真实Bot体验或测出线上缓存命中率。
