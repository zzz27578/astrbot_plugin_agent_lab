## 根据用户问题做的逻辑推演

| 情景 | 推演结果 |
| --- | --- |
| 计划没完成，管理员要求交付 | 直接进入administrator_end，列出未完成项；不调用verify_finish或LLM审批 |
| 有待审批/未知工具结果，管理员要求停止 | 先写终态，拒绝下一次工具派发；未知项留档，不阻止结束 |
| 旧模型稍后返回成功 | save_task拒绝终态写入，自动archive不会覆盖管理员归档，对话finally也不回写 |
| A已暂停，B正在运行，交付A | pause_execution仅取消活动指针确实对应A时的runner，不误停B |
| 同一会话从A切到B | A先暂停并收尾，B显式成为活动指针；普通保存A不会抢回指针 |
| 项目A摘要被项目B读取 | 自动上下文根据任务到项目映射及来源过滤，不读取全局模式库 |
| 日常对话连续讨论其他事情 | 只保留简短控制提示；不会加载项目工具全文。摘要共享关闭时不自动注入项目摘要 |
| 在项目页清理任务缓存 | 预览当前文件和精确任务cid，保留计划/摘要；源码目录不在候选清单 |
| 预览后新增记录或摘要变化 | 任务/项目内容摘要与文件mtime改变，token不一致，需重新预览 |
| 清理中断 | 留下last_cleanup状态；重新预览剩余内容，清理不重放任务工具 |
| Bot缺少关键范围信息 | 持久反问并暂停；管理员选项/自由回答入约束后再继续 |
| 素材库收起/目录展开 | 更新现有DOM类，触发真实过渡；不靠整图重建假装动画 |

这些推演不能替代真实I/O、浏览器或框架行为验证。

## 返工记录

首轮未达到交付门槛，已修正后复查：

- 结束一个非当前任务可能误取消同来源的另一个runner：改为核对task_id后才取消。
- 清理缓存后终态标记阻止归档文件压缩写回：清理路径显式写对应已确认记录，普通执行路径仍受终态保护。
- 自动交付可能晚于管理员结束返回并覆盖项目摘要：自动路径在关键await之后再次检查终态。
- 项目移动后旧项目可能保留来源摘要：移动任务摘要文件并清除旧项目的自动来源摘要。
- 前端开合重新渲染导致CSS过渡失效：目录/素材采用原DOM状态更新，抽屉关闭等待退出动画。
- 反问回答先标已回答、后追加约束可能失败：改为先校验约束容量，再一次保存状态。
- 新项目/任务按钮可能允许空目标：后端拒绝空目标，不自动替换成含糊任务。

## 前端评分的诚实边界

本轮采用10项可静态核对的交互清单：缩放默认值、嵌入布局、可调整面板、目录开合、明确后端动作、加载/错误反馈、草稿保留、键盘焦点、减少动态效果、无变化不重绘，均已实现并核对。

这可记为**交互实现清单10/10**；实际画面是否达到“大赛级”、拖拽是否丝滑、窄窗口是否完全符合个人习惯，**未评分**，因为没有浏览器实测。不能用主观自评8分或9分冒充已验证体验。

部署后建议优先体验：72%默认比例、素材左右切换与调宽、项目展开和任务切换、待回答与交付操作、存储预览/清理范围。真实体验低于预期时，应根据具体画面继续修整，不能靠提高自评分数结案。
