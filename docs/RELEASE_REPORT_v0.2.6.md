# v0.2.6 交付报告

日期：2026-11-11。基于 v0.2.5，继续以 AstrBot 4.29.4 为适配基准。

## 任务消息线

用户希望 Bot 像 Codex 一样在长任务中持续告诉管理员当前进度，同时不把进展、反问、审批拆成几套互相打架的机制。本版把它们收束到同一条任务消息线：每条消息带任务 ID和来源会话，类型为进展、需要回答、需要审批、状态或交付。

- 任务开始、有新检查点、等待条件变化时自动生成短消息。
- Bot 可以主动调用 `agent_lab_progress(message)` 补充1–600字；只写已确认结果、当前动作和下一步，不写完整工具日志、密钥或隐私。
- 反问直接给问题、选项、推荐和 `/al answer`；审批直接给操作、影响和 `/al approve`/`reject`；管理员交付也回到同一条线。
- 进展默认关闭。按机器人可在“设置 → 任务消息”打开并选择30秒到10分钟的最短间隔。相同内容去重，短时间内的新内容合并为待发摘要，最多80条进展。
- 必要控制消息不受进展开关阻挡。主动发送使用 AstrBot `context.send_message(UMO, MessageChain)`；发送失败会记录为未知，不自动重发。
- 消息日志单独写在任务 memory 目录的 `messages.json`，不会覆盖任务检查点。发送途中管理员停止任务时，终态文件优先，后续回写不会复活任务。
- 从 WebUI 结束已归档/非当前任务时，显式带上立项管理员身份，防止被清空的活动指针或另一任务的身份影响接收人。Bot 直接调用审批工具也走这条线；超长计划先显示批准/拒绝命令，再提供有限内容预览与详情提示。

这条线解决的是“Bot 做了很多轮后，管理员不知道它现在在哪”的问题。主动消息只发到原管理员私聊；不支持群聊主动简报。插件没有向日常 conversation 写入消息；对照 AstrBot 4.29.4 源码，`context.send_message` 的历史持久化分支仅处理群聊。任务正文和完整工具结果仍在项目记录中；真实平台行为仍需要部署联调。

## 真实机器人身份与默认选择

身份列表现在同时满足两个条件：AstrBot 配置里 `enable=true`，并且当前 `platform_manager.platform_insts` 已加载。未显式配置的内部 WebChat、历史 UMO 和已停用实例不会变成可选择机器人。历史项目数据仍保留；界面只显示当前实际实例对应项目，没有实例时显示空状态。

设置页单击切换查看范围，双击身份卡或点击“设为默认”会调用受管理员保护的 WorkspaceAPI，把默认实例保存到插件 `registry/workspace_preferences.json`。重新打开 iframe 或清掉浏览器 sessionStorage 后，仍从服务端恢复默认实例。项目创建和任务切换继续使用真实 UMO，显示切换不会改变执行 Bot、模型或 Persona。

## 素材库与后端能力同步

前端不再只靠一份手写的“看起来支持”的节点名单。`NodeExecutorRegistry.catalog()` 从后端当前注册的执行器、运行类型、执行模式和端口表生成 `state.node_capabilities`，工作流素材按它过滤和标注：

- 补齐 HTTP 请求、插件调用提示、敏感信息脱敏、经验规则草稿、任务记录、待发消息、记忆归档、执行范围与预算等实际后端动作。
- `scope_filter`、`retry`、审批、校验和通知节点使用后端真实端口表，前端不再把已有执行器显示成 ReAct。
- 心跳和定时入口继续隐藏；未实现的嵌套工作流显示为停用原因，不允许拖入新图。
- 资料卡显示“可执行”“需配置”“半自动”或“已停用”。文件、代码、API、提示等需要的字段在素材预览和节点编辑中明确提示。
- 任务记录提供来源变量与 JSON 内容编辑；无效 JSON 明确提示并阻止保存。顶部“保存”会一起保存当前节点编辑草稿，修复修改后漏点“应用节点”导致丢字段的问题。

能力导出脚本从 `main.py` 的执行器注册函数生成浏览器 fixture，测试数据和实际注册表保持同步。

## 画布连线和布局

原右侧工具栏、素材窗的位置和大小继续保留。连线使用独立 `connections.js`，从端口向外保留直线 stub，再按有限车道候选生成圆角正交路径，避开其它节点；普通路径使用 XYFlow 的圆角路径算法，手工 `route_hint` 仍优先。删除节点或移动节点不会再把新的自动路径写成旧的手工提示。

线条使用更深的蓝灰色、2.6px中心线、统一小箭头和清晰标签；悬停、选中、拖拽预览有独立状态。原碰撞检测仍作为命中层，不再把半透明旧通道叠在中心线下面。

画布页的侧栏明确复用项目页的 `--rail-width`、品牌字体、导航内距和存储底栏，避免进入画布后左侧突然放大。验证截图覆盖了1440、1100、820宽度，素材搜索框均能直接命中。

## 动效与可读性

灰色文字整体提高到可读对比度，placeholder、旧集成页、素材卡、节点辅助信息使用统一文字色。新增效果只在交互发生时运行：项目/预案/身份卡的指针局部光晕、按钮波纹、项目标题附近的阻尼波纹。没有常驻 requestAnimationFrame、WebGL 或定时唤醒；页面隐藏和“减少动态效果”会立即停止。

## 检查结果

- 真实 Edge 沙箱 iframe：**56项交互通过**，包括真实身份筛选、双击默认、服务端恢复、失效默认回退、消息设置和时间线、项目创建、预案管理、连线/撤销/重做/删除/保存、节点草稿保存与错误反馈、画布侧栏一致性和真实素材选择器过滤。
- 后端真实模块、临时文件、Quart 客户端：**19项通过**，包括身份配置过滤、默认实例持久化、进展设置、任务消息去重限频与合并、问答/审批共线、管理员终态优先、发送失败不重播、归档后的接收人、清理途中不重建记录、私聊发送不写日常记录、独立WebUI资源路由。
- 路由模块：**6种场景、30项断言通过**，覆盖正向、反向、重试端口和障碍物；检查正交线段、端口方向与中间路径避障。
- 静态契约：10/10；Python源码可解析；JS语法和CSS解析通过；能力表由后端注册自动导出。
- 三种宽度无横向溢出，素材搜索框未被顶栏覆盖，浏览器无未捕获异常。

本轮没有启动完整 AstrBot、真实平台账户或真实模型。主动发送接口已对照 AstrBot 4.29.4 源码核对，但真实 QQ/Telegram 等平台投递仍需你的部署环境验证。未做千级节点、超大历史目录和移动触摸压测。

## 资源和维护

前端入口资源（含新增 connections.js、motion.js）合计约 **789KB**，逐文件离线 gzip 合计约 **199KB**，详见截图目录的 `asset-sizes.json`；这是未含图片的文件体积，实际网络压缩取决于宿主配置。连线路径 vendor 仍为4KB级，不引入 React/Svelte/D3运行时。消息分发器不额外请求模型，`agent_lab_progress` 使用 Bot 写出的短文本；Bot 生成文本和调用工具仍有常规模型/上下文开销。

本轮把消息、偏好、连线和动效分别放在独立模块；`main.py` 仅连接原有入口，素材能力由后端一份注册表提供，合并重复连线 CSS，避免再复制一套执行器或模型会话。自动路径缓存最多512项，消息日志最多80项；进展限频且最多80次。发送有3秒/10秒超时上限，失败去重，管理员结束不等待模型验收。现有 `main.py` 仍很大，这次只收束新增职责，没有宣称已完成全仓拆分。

测试命令和 mock 边界见 [scripts/ui/README.md](../scripts/ui/README.md)。截图和 JSON 结果在 [docs/screenshots/v0.2.6](screenshots/v0.2.6/)。
