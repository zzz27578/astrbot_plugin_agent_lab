# v0.2.3 更新报告：在原设计上补强 Bot 的任务工具

日期：2026-11-10。基线是恢复后的 v0.2.2；适配参照 AstrBot v4.29.4。

## 保留了什么

原页面结构、绿色配色、全屏画布、素材库和五个外部方案模块 JSON 均保留。条件分支、循环/重试、并行、子流程、子代理泳道/领地、API、凭证、记忆、报告、审批和定时模块没有缩成另一套简化工作台。

没有新增 React 项目或独立任务模型选择器。主任务使用来源 Bot 的当前模型和 Persona；子代理显式配置的模型覆盖保留。旧方案、节点及任务文件继续使用原结构，不进行全量数据库迁移。

## Bot 怎么更好用

1. Bot 接到长任务后可以调用 `agent_lab_workflow_catalog`，只先看可选方案的标题、简介和 ID。
2. 没有适合的方案，就以 `workflow_mode=none` 直接立项；指定方案则传 `selected` 和方案 ID。具体任务计划与画布步骤分开保存。
3. 可以直接交付 plan_json；没有时借用 Bot 当前模型草拟具体计划。管理员通过原有审批按钮或命令确认计划版本。
4. 批准后自动推进一轮轮有上限的工作。工具结果返回证据 ID；Bot 用 `agent_lab_checkpoint` 保存当前步骤与结果。分析步骤可保存独立报告，报告不会被当成实际测试已通过。
5. 每轮重新加载原始目标、批准版本、当前步骤、约束、近期工具记录和接续位置。任务对话存到单独的原生 conversation，不切换日常当前对话。
6. 管理员途中说“保留配置格式”等要求，可由 Bot 用 `agent_lab_steer` 转交；这些要求进入任务持久约束，下一决策边界读取。
7. 高风险动作审批、暂停、取消、错误、无进展和预算限制会停止推进；服务重载后需明确恢复，未知外部操作结果需先核对。

新命令补充：`/al plan <步骤JSON>`、`/al steer <要求>`、`/al pause`、`/al resume`。原命令与审批入口继续保留。WebUI 原任务页增加计划显示/修订、引导与工具结果核对，不要求用户必须通过网页立项。

一次来源仍沿用原来的单活动任务约束，避免此次悄悄改变任务选择与命令语义。不同任务的完整记录、计划、报告和原生对话独立存储；共享范围沿用来源与明确接受规则，不在归档时自动公开摘要。

## 后端更正

| 原问题 | 本版处理 |
| --- | --- |
| 工具上下文格式不符合新版、直接 tool.call 不支持部分工具 | 统一构造 AstrAgentContext，调用原生 FunctionToolExecutor；保留框架权限包装 |
| 模型停轮后需要人工反复继续 | 已批准任务由执行结束驱动下一轮，保留总预算和重复失败/无进展停止条件 |
| 计划只是画布节点列表，具体任务进度不稳定 | 在原 TaskState.workflow_data 增加 task_control，记录具体计划版本、批准版本、步骤、约束与工具记录 |
| 全量任务信息进入日常聊天、进入任务关闭日常插件 | 日常仅注入任务入口/简短状态；执行工具集继续按方案约束，日常插件不被关闭 |
| 审批/暂停仅提示模型 | 工具执行前重新检查当前任务、计划、管理员、审批与预算；高风险调用绑定具体参数与资源配置 |
| 工作流直接代码节点写死本机 powershell/python | 使用原生 Shell/Python/文件工具，尊重 AstrBot 配置的环境与权限 |
| 删除旧归档可能取消新任务 | 先核对选择的 task_id，删除历史任务不会把当前活动任务 ID 覆盖进去 |
| 归档后外层保存复活任务 | 保存终态不再生成活动任务文件；runner 检查任务是否已结束再保存 |
| 状态靠中文提示词猜 | service 从持久任务状态返回结构化状态，不再用“失败/暂停”子串判断 |
| 访问过节点就算完成 | 根据节点最近执行事件区分成功、阻塞、跳过；当前具体计划另有工具证据检查 |
| 新调用 ID/日志时间可伪装进展 | 任务进展根据工具结果指纹、成功节点与步骤状态判断，报告改写本身不重置进展 |
| 主循环/压缩沿用旧参数 | 新版原生 runner/压缩配置集中适配，每次模型响应（含压缩）计入用量 |
| 定时创建虚假 QQ 来源 | 使用真实 schedule_target_umo、schedule_admin_id；重新鉴权，立项仍等待计划批准 |
| API 提供商选项能保存却不能调用 | URL 为空且绑定 provider_id 时按 body_json.prompt 实际调用已配置提供商，不复制密钥 |
| 登录态刷新只改时间却报成功 | 保留节点配置，明确未绑定真实刷新能力时阻塞并说明；不假称远端已刷新 |

并行模型工作包与子代理仍保留。其原生工具派发在同一任务内使用串行保护，避免共享状态和副作用并发覆盖；模型分析仍可并行，子任务会话分开。并行结果要求明确结构化状态与证据，不能仅收到一段文字就报告成功。

工具调用取消或超时并不保证外部动作被撤销。记录为 started/unknown 的调用会阻止自动恢复，管理员可在原任务页核对 completed/failed/not_started 并填写依据。

## 如何降低继续堆积代码的风险

- `task_control.py`：只负责具体任务计划、审批衔接、检查点、引导、续轮与重载恢复。
- `astrbot_bridge.py`：集中处理原生模型/Persona/工具/压缩/任务对话适配，主 Bot 不新增独立配置。
- `node_policy.py`：复用原节点执行器，统一每次节点执行前检查、重试与外部操作记录，不复制所有节点业务实现。
- `web_api.py`：统一管理员入口和可预期业务错误反馈。
- `ui-runtime.js`：浏览器存储安全回退与表单草稿保留，避免各个按钮自行处理不同规则。

主文件仍承载历史节点业务，不能说已经彻底消除技术债。本版先将新增跨流程规则放到明确边界，并替换重复/错误路径；原复杂模块继续可追溯，后续可逐组迁出，不靠删除原功能来减小文件。

借鉴机制：参考 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 的事件续轮、输入与未知结果处理；参考 [Codex 持续任务](https://learn.chatgpt.com/docs/long-running-work) 的持续目标和验收边界；参考 [Claude Code 压缩恢复](https://code.claude.com/docs/en/context-window#what-survives-compaction) 的计划/规则重载。它们落实为现有 TaskState 上的控制记录，不安装这些 CLI 或另一套 Agent 框架。

## 前端与连线

- 保留全屏布局和配色，新增按钮悬停/按下、焦点、节点高亮、抽屉进入、连线预览和忙碌状态反馈；支持减少动态效果的系统偏好。
- 高频 pointer/wheel 更新合并到动画帧；节点查询使用索引，避免每次查询重做全图迁移。
- 平移和缩放仅更新视口；拖线只更新预览线。拖节点期间使用路径缓存与轻量路由，结束后重算必要路线，小地图不再每次拖动重建。
- 保留原连线形状、条件、端口和剪刀模式；普通点击线先选中，Delete 明确删除并可撤销，Esc 取消。
- 不再将空节点/空边当缺配置自动重建；旧模板 ID 也不会触发整图替换。
- 原生 bridge 与独立 fetch 都检查业务错误。创建失败不显示固定成功，模拟触发只诊断不执行，手动推进显示真实结果。
- 任务静默刷新保留表单草稿和焦点；提交中有忙碌反馈和重复点击保护。
- 修正受限 iframe 的 Storage 访问和 URL base 构造，独立控制台新增脚本资源路由。

本版没有立刻换图库。AntV X6 仍是后续局部替换的候选，但需要先完成原端口/循环/领地/路由字段的完整映射；先修现有性能热点可以避免再次破坏原设计。实际顺滑程度不在静态检查中宣称通过。

## 权限与配置变化

默认完全关闭群聊任务入口；管理员集合由 AstrBot admins_id 与 workflow_admin_ids 合并。原生 WebUI 验证 Dashboard 登录身份，独立控制台所有地址都要求 Token。

原审批策略可继续使用。若要批准某工具在本任务中免重复审批，可明确设置 `preapproved_scopes` 为 `tool:精确工具名`，计划审批会展示此范围；自然语言说明不会被悄悄解释成机器级授权。批准工具名意味着覆盖该工具参数，需管理员明确确认。

最低 AstrBot 声明改为 4.29.4；Python 版本跟随该版 AstrBot 要求。旧文件不删除、不自动改造成另一种工作台。

## 验证范围与需要实际验收的部分

已完成：Python AST 解析、JavaScript `node --check`、配置 JSON/版本/API 装饰器/原模块与资源静态检查、Git 差异检查，以及针对批准、暂停、归档、续轮和按钮调用链的源码核对。

按维护者要求，没有启动 AstrBot、插件、模型、实际工具或浏览器，没有宣称运行测试或 FPS/手感验收通过。实际模型的计划输出质量、平台通知、第三方工具行为、不同原生执行后端和画布手感仍需部署验证。

建议首先验收：Bot 自己立项与选/跳过画布 → 审批计划 → 连续多轮后步骤不丢 → 途中补要求 → 暂停/恢复 → 任务收尾；然后检查旧复杂画布的循环、并行和节点参数。遇到真实问题应继续在原设计上修正。
