## 修复：切断内容反复进入模型的路径

1. **读文件按版本与行范围复用。** 本地文本文件校验绝对路径、大小、mtime、ctime、inode和宿主配置；原有权限检查仍先执行。跨轮已读区间可复用，重叠请求只调用工具读取缺口。文件或宿主配置变化就重新读取。无法取得可信版本的远程运行环境保留保守行为，不声称有跨轮缓存。
2. **先给小窗口，后续精确接读。** 普通本地文本每次至多120行，模型可见正文受5000字符预算限制。明确标注实际行范围、完整证据ID和后续偏移；完整已读结果保存，超过可见预算时按字符读证据，不需要缩小范围重新执行原工具。
3. **历史工作视图有界。** 发给模型前，把旧的文件/搜索/状态/证据结果替换为短预览及证据索引；未签名的历史编辑参数也索引化。保留工具调用与结果ID配对，保留协议要求的签名和已签名调用，避免破坏模型兼容性。原始会话及证据仍完整存档。
4. **状态与计划不再复印代码。** `read_state(summary)`只给短状态及最近证据索引；持久计划不再逐轮注入大段`old/new/content`和工具全文。需要细节时按证据ID回查。

## 修复：交接不再对整份原消息反复写报告

交接记录仍先保存完整原始消息。真正送给总结模型的是另一份精简材料：移除思考、加密签名、媒体载荷，把工具输出与大段编辑代码转成证据索引。它服务本任务下一步，保留已改哪里、实际验证、未完成什么和下一步；不要求写满长度。

工作摘要按计划规模设800–1600字符目标，仍不超过管理员配置及模型容量预算。空正文重拉一次，超长正文要求压缩一次；最多两次模型请求。仍异常时使用明确标注的降级工作视图，保留异常正文与原始材料，要求回查证据，不把降级当作验证通过。错误记录区分`empty`/`too_long`，包括实际字符数、上限、尝试次数及游标。

管理员停止、任务切换、磁盘错误和Token预算仍优先，不能被摘要兜底吞掉。旧草稿的原始消息与旧游标/摘要保留；旧游标不能用于新精简材料，恢复时从新材料开头重新汇总，避免错段。
